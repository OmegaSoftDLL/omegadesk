# Changelog

All notable changes to OmegaDesk are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project will follow [Semantic Versioning](https://semver.org/) once it has releases.

## [Unreleased]

### Added

- Phase 7 virtual display, wired into the agent: a real Windows Indirect Display (IddCx) driver replaces the old placeholder `drivers/idd` crate (which was an invalid INF plus bare IOCTL constants with no driver). The MIT-licensed [QuickDesk](https://github.com/barry-ran/QuickDesk) driver is vendored under `drivers/idd/vendor/` — the kernel driver ships prebuilt and EV-signed (`quickdesk_display.dll/.cat/.inf`, not built in CI since it needs the WDK/IddCx) and `build.rs` compiles the user-mode controller (`IddController.c`) with the normal Windows SDK via `cc`. `omegadesk-idd` exposes a safe API: `VirtualDisplay::install`/`open`/`is_installed`/`uninstall` (install/remove through the bundled `nefconw.exe`, idempotent, needs administrator rights with a typed `NotElevated` error), `plug_monitor(DisplayMode) -> MonitorHandle`, and `MonitorHandle::set_mode`/`unplug`. It is Windows-only at runtime; off Windows every operation returns a clear `Error::Unsupported` and the API still compiles and unit-tests on Linux and macOS. The agent gains `--virtual-display <WxH@hz>` (plug a virtual monitor on a headless host, installing the driver on first use) and a `--privacy` mode that also blanks the physical monitor (restored on exit), backing the `crates/capture/src/virtual_display.rs` `VirtualDisplayManager` placement model with the driver. Attribution in `THIRD_PARTY.md` and `drivers/idd/README.md`; MIT license kept in `drivers/idd/vendor/LICENSE`.
- Phase 4 browser client end to end: `omegadesk-server --web-listen <addr>` serves the page from `web/dist` and proxies each browser `WebSocket` to an agent chosen by name over the mesh (the server joins as `web-gateway.omega` with a reusable pre-auth key it issues itself): `Hello` with the password typed in the browser, `HelloAck`, the video stream re-framed as `omegadesk-web-video/1` under the Selkies per-frame ACK gate, keyboard (`KeyboardEvent.code` → HID usage + keysym, noVNC tables), pointer and keyframe requests relayed on the control stream, `Ping`/`Pong` and per-second `stats` (`server/src/web_server.rs`, `web_session.rs`; JSON control contract `omegadesk-web-control/1` in `web_gateway.rs` with shared fixtures). The page (`web/public/index.html`, `web/src/main.ts`, `protocol.ts`, `input.ts`) decodes H.264 in the `WebCodecs` worker and shows an estimated glass-to-glass latency. `web/` now has a real `package.json` (`typescript`, `node --test` type-stripped unit tests for framing, control protocol and input helpers, `tsc --strict` build to `web/dist`) and a CI job on Node 22; `server/tests/web_gateway_e2e.rs` runs coordinator, relay, an agent node speaking the real protobuf session protocol, the gateway and a `WebSocket` client, including password, unknown-agent, `Origin` and `Host` rejections. Flags: `--web-root`, `--web-allowed-host`, `--web-behind-tls`, `--web-key-file`, `--web-mesh-bind`, `--web-relay-only`.
- Phase 3 Windows unattended access, wired into `omegadesk-agent` (crate `omegadesk-service`): `omegadesk-agent service install|uninstall|start|stop|run` registers and controls a `LocalSystem` Service Control Manager service (via the MIT/Apache `windows-service` crate, ported from RustDesk `src/platform/windows.rs::run_service`) that accepts `SERVICE_ACCEPT_STOP | SHUTDOWN | SESSION_CHANGE`. The service supervises a per-session capture/input **worker** launched in the active console session with that session's `winlogon.exe` SYSTEM token (`OpenProcessToken` + `DuplicateTokenEx` + `CreateProcessAsUserW` onto `winsta0\default`, ported from RustDesk `GetSessionUserTokenWin`/`LaunchProcessWin` and Aspia's `host_service`/`user_session` split), relaunching it on `WTS_CONSOLE_CONNECT`/`WTS_SESSION_LOGON`/RDP handoff and on crash. Running as SYSTEM, the worker follows the input desktop with `SetThreadDesktop` (so capture and injection keep working across the login screen, the UAC secure desktop and the lock screen), captures through the fallback chain, injects remote keyboard/pointer events, and blanks the local screen in privacy mode. Service and worker communicate over a named pipe (`\\.\pipe\omegadesk-service.*`) with length-delimited `ServiceEnvelope` protobuf framing added to `omegadesk-protocol`. Unit tests cover the supervisor/session state machine, the IPC framing and the argument parsing; a Windows-only `#[ignore]`d integration test drives the install/start/stop/uninstall lifecycle through the built binary under Administrator.
- Windows Graphics Capture (WGC) backend (`crates/capture/src/wgc.rs`, ported from Sunshine `display_wgc.cpp`), making `open_display`'s fallback chain the full `DXGI -> WGC -> GDI` (`open_display_tracked` also reports which backend opened): WGC composites a monitor through DWM into Direct3D11 textures, covering cases where `IDXGIOutputDuplication` refuses to start, with GDI `BitBlt` as the last resort.
- Real privacy mode that blanks the local screen: a fullscreen opaque black overlay window marked `WDA_EXCLUDEFROMCAPTURE` is shown on the physical monitor but excluded from the DXGI/WGC capture, so the local person sees black while the remote operator still sees the desktop. `set_excluded_from_capture` is the reusable, connection-scoped exclusion primitive. This replaces the earlier ownership-only state machine, which blanked nothing.
- QuickSupport end to end (Phase 3): `omegadesk-quicksupport` joins the mesh as an ephemeral node, shows a nine-digit ID and a temporary password, asks the end user for consent on the console and serves the screen with the agent's session code; `omegadesk-client 123 456 789 --server …` resolves the ID through the coordinator and connects over the mesh (digits with or without spaces or dashes). The coordinator gained a tenant-scoped QuickSupport ID registry (RustDesk `RegisterPk` model: the node proposes the ID derived from its device identity, the coordinator keeps it when free or already owned by that device and assigns a random free one otherwise, and releases it on disconnect), `Coordinator::enroll_quicksupport` / `lookup_quicksupport`, and a `quicksupport_preauth_key` printed at startup. Control protocol: `EnrollRequest.quicksupport_id`, `NodeInfo.quicksupport_id`, `QuickSupportLookupRequest` / `QuickSupportLookupResponse` and `CONTROL_ERROR_CODE_MALFORMED_REQUEST`, all with new field numbers. `omegadesk-identity::QuickSupportId` (parse, format, proposal), `omegadesk-control::ControlHandle::lookup_quicksupport`, `omegadesk-magicsock::Node::{lookup_quicksupport, connect_quicksupport, connect_peer, quicksupport_id}`. `omegadesk-agent` is now a library plus a binary: `session::SessionGate` is consulted after the password check and before `HelloAck` (the agent runs without a gate), a wrong password is reported as `password::Rejected`, and `TemporaryPasswordGuard::record_failure` rotates after ten externally verified failures. An in-process end-to-end test runs coordinator, relay, QuickSupport host and technician through ID lookup, tenant scope, expiry, QUIC connection and the gated handshake.
- Phase 3 session channels wired end to end between `omegadesk-agent` and `omegadesk-client`: text clipboard synchronization in both directions through `arboard` with the existing SHA-256 echo suppression (`--no-clipboard`); file transfer in both directions on one QUIC stream per file with 64 KiB chunks, resume from a `.odpart` partial negotiated through the first `FileTransferAck` (RustDesk `OffsetBlk` model), SHA-256 verification before the final rename, no overwrite of existing files, `--send-file`, `--receive-dir` and drag-and-drop onto the client window; multi-monitor switching (`omegadesk-capture::list_displays`, `DisplayList` published by the agent, `Ctrl+Alt+Shift` + `1`..`9`/`N`/`P` in the client, capture retargeted on the agent); and video QoS (the client acknowledges every decoded frame with `FrameAck`, the agent drives `VideoQosController`, paces capture to its frame rate and retunes the encoder bitrate, live on Media Foundation through `ICodecAPI`, by restart on OpenH264). `omegadesk-session` gained the `io` feature (`clipboard_io`, `file_io`) with loopback QUIC tests, and `VideoEncoder::set_bitrate` was added to `omegadesk-codec`.
- Phase 2 end to end: `omegadesk-control` (node-side client of the coordinator: Noise `IK` enrollment, netmap stream, relay ticket refresh, endpoint updates, automatic re-enrollment with back-off and full resync), `omegadesk-magicsock` (one UDP socket multiplexing STUN, `disco` and tunnel data; DERP-style relay connections with challenge-bound logins, fresh-ticket reconnects and `PeerGone` steering; a `quinn::AsyncUdpSocket` giving every peer a stable virtual address `<mesh IPv4>:7070` so QUIC never notices a direct/relay switch), identity-bound QUIC TLS (`omegadesk-transport::identity_tls`: Ed25519 certificate carrying the node key, verified against the netmap), and `--server`/`--server-key`/`--preauth-key`/`--relay-only` on `omegadesk-agent` and `omegadesk-client` (connect by `name.omega`; without them the Phase 1 LAN mode is unchanged). An in-process end-to-end test runs coordinator, relay and two nodes with direct-path upgrade and relay-only sessions.
- Phase 7 groundwork, library only and not wired into any binary (compatibility and differentiators): `omegadesk-rdp` (`RdCleanPathPdu` and `RdCleanPathErr` browser-to-mesh RDP proxy framing ported from IronRDP `ironrdp-rdcleanpath`, `[MS-RDPEDISP]` `DisplayControlPdu` dynamic monitor layout PDUs ported from IronRDP `ironrdp-displaycontrol`, and `VncCongestionController` TCP-Vegas latency-based RFB congestion control ported from TigerVNC `Congestion.cxx`), `omegadesk-mcp` (`McpTrustEngine`, `TrustPolicy`, `RiskLevel`, `DangerousPattern`, `assess_risk`/`base_risk`, operator confirmation gating, audit log, and emergency kill-switch ported from QuickDesk `quickdesk-mcp/src/trust.rs`), `omegadesk-capture::virtual_display` (`VirtualDisplayManager`, deterministic client GUID `derive_virtual_display_guid`, `DriverStatus`, headless mode, and isolated lower-right monitor placement ported from Apollo `virtual_display.cpp`, plus Linux `PipeWireDmaBuf`/`KmsDrm` and macOS `ScreenCaptureKit` backend selection), and `omegadesk-mesh::peer_routing` (Nebula-style Ed25519-signed `PeerRelayCertificate` and coordinator-free `LinkStateRouter` OSPF Dijkstra shortest-path routing).
- Phase 6 groundwork, library only and not wired into any binary (RMM (remote monitoring and management)): `omegadesk-server::rmm` (`DeviceInventory` with memory/storage utilization ratios, `DriveInventory`, `WindowsUpdateStatus`, and custom fields ported from Remotely `Device.cs`; `SavedScript`, `ScriptingShell`, `RepeatInterval`, `ScriptSchedule`, and `ScriptScheduler` with `run_on_next_connect` offline queueing ported from Remotely `ScriptScheduler.cs` and `ScriptScheduleDispatcher.cs`; `DeploymentLinkManager` per-site expiring HMAC-SHA256 enrollment tokens; `AgentUpdateManager` chunked binary streaming `cmd 10`/`13`/`14` with `taskLimiter` concurrency limiting ported from MeshCentral `meshagent.js`; and `AgentTopic` identity-bound `agent.<device_id>.<channel>` mesh topics) and `omegadesk-policy::rmm_policy` (`resolve_effective_rmm_policy` hierarchical `Tenant -> Site -> Device` policy inheritance, `RmmCheck` + `CheckEvaluator` + `AlertTemplate` failure/resolution actions, and `ScopedRmmRole` with `can_*` `RmmCapabilityFlags`).

### Changed

- Phase 2 (mesh) was validated in a two-machine test over Tailscale (coordinator + relay + agent on a second Windows host, client on another): enrollment, `*.omega` name resolution, relay login, STUN + `disco` hole punching and the QUIC session all worked, and the receiving side held a direct path with no fallback. `docs/plan.md` records the one known issue (a heavily multi-homed sender can still see brief path churn) and marks Phase 2 status accordingly.
- `omegadesk-quicksupport::format_quicksupport_id` formats the ID as `123 456 789` (spaces, not dashes) and returns the *proposed* ID; the coordinator may assign another one. The crate's mesh and session integration sits behind the default `host` feature, which `omegadesk-policy` turns off. `omegadesk-control::ControlConfig` and `PeerInfo` gained a `quicksupport_id` field.
- `omegadesk-agent`: `--bitrate-mbps` and `--fps` are now the ceilings of the adaptive controller (the stream starts at RustDesk's `INIT_FPS` of 30 and ramps up within a few acknowledgements), and `--display` selects the initial monitor that the client may switch away from. The agent accepts bidirectional QUIC streams for file transfers in addition to the control stream.
- `omegadesk-mesh`: tunnel keys are now direction-specific and bound to a per-process epoch (header carries the sender epoch), with STUN reflexive discovery, probe expiry, direct-path trust/heartbeats and automatic fallback when a validated path dies; `MeshNode::new` takes the STUN servers, `encapsulate` no longer takes a clock, `ipv4_udp` returns an error for oversized payloads, `LinkStateRouter` requires verified relay certificates, and `finalize` was removed from the Noise initiator (use `complete`).
- `omegadesk-relay`: tickets name the relay they are valid on and carry a 120-byte wire format; the login frame is sealed with the client's key; `RelayRouter::new` takes the relay identity and `register_client` returns a `RegisteredClient` with a connection generation. The relay binary requires `--ticket-secret-hex`, persists its identity, serves STUN on UDP, and validates frame lengths before allocating.
- `omegadesk-server`: a registered node reconnects with the pre-auth key it enrolled with even after that key was consumed or expired (Headscale model); a removed ephemeral node needs a usable key again. `EnrollResponse` and `NetmapBatch` are chunked to fit one Noise frame, control writes time out, and enrollment generations make a late disconnect of an old connection harmless.
- `omegadesk-control`: `NetmapEvent::PeerUpserted` carries a `Box<PeerInfo>`.
- `omegadesk-server`: netmap snapshots and deltas are scoped to the node's tenant; the binary keeps the control stream open and speaks the new `omegadesk.control.v1` protocol (`EnrollRequest`/`EnrollResponse`, `NetmapBatch`, `EndpointUpdate`, `RelayTicketRequest`, `Keepalive`), persists its identity and requires `--ticket-secret-hex`; relays are configured with `--relay host:port=<key>`.

- The build plan (`docs/plan.md`) and the README no longer mark Phases 2–7 as done. The 2026-11-01 audit found that the crates added for those phases are not used by any binary, that 78 Copilot Code Review findings on PRs #17–#24 were merged without a fix, and that several claims (IronRDP, IddCx driver, MCP server, Linux/macOS capture, SSO/WebAuthn) describe data types rather than working features. Each item now carries an honest status and its known defects.
- `release-plz.toml` covers every workspace crate, so the lockstep version applies to the crates added for Phases 2–7.

### Removed

- `client/src/pacer.rs`, a frame pacer that was never called (`#[allow(dead_code)]`); the client bounds latency with its 3-frame decode queue and latest-frame presentation.

### Fixed

- `omegadesk-mesh`: direct-path liveness is decided by the explicit liveness `Ping`/`Pong` (500 ms of silence under traffic sends a `Ping`; no `Pong` within 1 s abandons the path), and a `Pong` answering a `Ping` sent to the validated address refreshes trust even when it returns from another address of the peer. A peer that sends its own traffic through the relay while still answering pings no longer makes this side flap every 2 s (second cross-machine test).
- `omegadesk-mesh`: a direct path no longer flaps to the relay every 1.5 s when the peer answers from another of its addresses (double NAT: LAN address versus the router's address). Any authenticated packet that arrives directly now counts as liveness, whichever alias it came from. Found in the first cross-machine test of Phase 2.
- The agent and the client no longer fail to start where the OS credential store is unavailable (Windows Credential Manager inside SSH or service sessions reports `ERROR_NO_SUCH_LOGON_SESSION`): the identity falls back to `<config>/omegadesk/<account>.key` with a warning, and `--key-file` (`OMEGADESK_AGENT_KEY_FILE` / `OMEGADESK_CLIENT_KEY_FILE`) selects an explicit file, as the server and relay already allowed. Found while starting the agent on a second machine over SSH.
- Phase 5 review findings from #29 and #33 (`omegadesk-policy`, `omegadesk-recording`, `web/src/recording-player.ts`): `autogroup:self` ACL sources given as `hosts` aliases or literal IPs are restricted to the untagged devices of the target's owner; SSH `Check` rules take precedence over earlier `Accept` rules and the `autogroup:self` ownership check is applied per destination; per-connection MFA challenges are single-use through `ConnectionMfaVerifier`, which also remembers every accepted TOTP counter per user; `AccessTicket::new` rejects an empty approval workflow instead of auto-approving; share links naming another session are rejected by `LiveSessionController`; a configured `NetworkRangeRule` with an empty allow-list fails closed; `OdrecWriter` indexes only records flagged `KEYFRAME` and `seek_keyframe` never returns a later keyframe; the browser player rejects a trailing partial record header and `play()` actually schedules and delivers frames with pause and end-of-stream handling.
- Phase 3 library review findings (#27): `omegadesk-session` file transfer bounds every chunk by the offer's `total_bytes` before buffering (`ChannelError::FileSizeExceeded`), sends exactly one EOF chunk for 0-byte and fully-resumed files instead of panicking or never completing, and `FileTransferReceiver::into_bytes()` is fallible (`partial_bytes()` for resume, `TransferClosed` after completion or failure); clipboard deduplication keys on `(format, SHA-256)` so the same bytes as text and then HTML both reach the peer; serverless LAN mDNS host labels are capped at 63 bytes.
- Phase 4 library review findings (#28): `omegadesk-policy` rejects moving a device group to another tenant while devices are enrolled (`PolicyError::DeviceGroupTenantChange`) and drops a tenant's stale SNI bindings on update; the RDCMan `.rdg` and PuTTY XML importers walk a real element tree so nested groups keep their parent, group properties come only from direct children, the `inherit` attribute drives inheritance (including console session), PuTTY folders are recreated, and XML character references are decoded; the web gateway `RequestRateBudget` is a true sliding window, the frame backpressure stall timer restarts when the in-flight queue becomes non-empty, browser key translation covers punctuation, function, navigation, lock and numpad keys with right-hand modifier keysyms chosen from `code`; the browser video path uses one documented binary contract (`omegadesk-web-video/1`: `0x04` frame with 12-byte header, `0x06` client ACK) shared with `web/src/video.ts`, ACKs frames after rendering (discarded frames are ACKed immediately), recreates the `VideoDecoder` after recoverable errors, reports unsupported configurations as fatal, and forwards `request-keyframe` over the session control channel.
- Phase 6 and 7 review findings from #30 and #31 (all but the `peer_routing` items): RMM script schedules only target devices whose inventory belongs to the schedule's tenant; `Monthly` recurrence advances by calendar month anchored to the new `ScriptSchedule::start_at_unix_secs` (Remotely `StartAt.AddMonths(i)`) instead of a fixed 30 days; deployment link tokens are hex-decoded and checked with constant-time `ring::hmac::verify`; agent binary transfers pin an immutable image snapshot for every chunk and the completion hash, and release their `taskLimiter` slot on disconnect (`cancel_transfer`), on stall (`expire_stalled_transfers`) and when a reconnecting agent restarts its download; MCP `blocked_tools` take precedence over `auto_approve_tools`; a virtual display update keeps the client's origin and reflows other displays only on overlap, and placement includes the real physical monitor bounds (`DisplayBounds`) instead of assuming one 1920x1080 desktop; `[MS-RDPEDISP]` monitor layouts are validated against `200..=8192` and the even-width rule on encode and decode; and the VNC congestion controller resets its window and RTT baseline when sending resumes after an idle pause.
- GDI capture fallback no longer busy-polls a static desktop: it honors the timeout given by the caller, polls `BitBlt` at 30 Hz, and deselects the bitmap before `GetDIBits` as Win32 requires.
- GDI capture is tried when DXGI reports no output for the requested display, so GDI-only displays (basic display adapter, nested RDP) can be shared.
- HDR FP16 tone mapping uses the exact sRGB transfer function instead of a 1/2.2 gamma that lifted dark pixels.
- Horizontal mouse wheel direction in the Windows client (`winit` sign inversion relative to `MOUSEEVENTF_HWHEEL`).
- Keys and mouse buttons no longer stay pressed on the remote machine when the session drops or the client loses focus.
- The agent never re-sends an old screen image after losing access to the display (lock screen, UAC).
- The Windows 11 power throttling (EcoQoS) no longer slows the agent down.
